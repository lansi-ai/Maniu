# T-187 S1：客户端自研的第一条竖切

范围只到「壳起宿主 → 登录门禁 → 列会话 → 发一条 → 流式正文 → 重启读历史」。工作台五页、Markdown 阅读器、审批/提问卡片、附件都不在 S1。

## 组成

| 包 | 角色 |
| --- | --- |
| `packages/lcoder/desktop` | Electron 主进程；宿主子进程监督、协议适配层、窄 IPC、frameless 窗口 |
| `packages/lcoder/client` | 渲染端（React 18 + Vite）；登录门禁、会话列表、聊天 |
| `lcoder/s1-profile.patch.yml` | S1 的最小宿主 profile 追加层（`dsh-base` + `dsh-web-app` 之上）；T-197 起启动器改落发布 profile `profiles/lcoder`，本文件只保留为 S1 的历史最小组合 |

宿主入口是 `packages/lcoder/desktop/src/host-entry.ts`：它复用 `desktop` 的 `runProfile` 启动语义，但**不装配** `apps/desktop-host` 的 Office 与平台插件，因此不依赖 `.desktop-build` 里的 office 载荷。宿主 home 一律是仓内 `.dsh-home`（已被 `.gitignore` 忽略）。

## 构建

```sh
export pnpm_config_verify_deps_before_run=false
pnpm --filter @lcoder/desktop --filter @lcoder/client run build
```

产物：`packages/lcoder/desktop/lib/types/main.js`、`lib/preload.cjs`、`packages/lcoder/client/lib/dist/index.html`。

## 启动（本工作树专用端口）

```sh
pnpm --filter @lcoder/desktop run launch
```

默认 inspector：主进程 9829、渲染调试 9822、宿主 9830（`DSH_DESKTOP_MAIN_INSPECT_PORT` / `DSH_DESKTOP_RENDERER_DEBUG_PORT` / `DSH_DESKTOP_HOST_INSPECT_PORT` 可覆盖）。`DSH_HOME` 默认 `<本树>/.dsh-home`。

模型默认走 `lcoder-cloud`（发布 profile 的 `llm-pi-ai` 配置），地址由 `LCODER_CLOUD_BASE_URL` 覆盖；不设时指向本机 mock `http://127.0.0.1:5091/v1`。无可用云端或令牌时门禁显示「云端不可用」，不会被当成未登录。

## 探针

```sh
node lcoder/scripts/t187-s1-probe.mjs
```

探针自己拉 mock 云端、登录专用测试号（`+8613900000001`）并把令牌写进 `.dsh-home/.credentials.yaml`，然后经 CDP 断言：

1. 窗口与渲染进程起来；
2. 宿主 `ready`，登录门禁放行；
3. 新建会话后列表非空；
4. 发送一条消息后出现 assistant 文本；
5. 关掉重启后，点同一会话能从 `session.follow` 的 snapshot 重读历史。

通过时退出码 0 并打印 `PASS`；失败退出码 1，日志在 `lcoder/logs/t187-probe-*.log`。

## 安全边界

- 渲染端无 Node、无 `fetch`、无宿主 cookie；只能经 preload 的 `call` / `stream` / `events` / `eventResult` / `window`。
- 适配层只放行 S1 需要的命名空间与方法（`lcoderCloud/state`、`session/list|create|prompt|cancel`、`session/follow` 流），不透传任意路径。
- `/connect` 必须带 `interactions=answer`，否则 `$events` 会被网关拒绝。
- `.spec` 的写入仍只走 `commands.execute`；S1 不直接写磁盘。
